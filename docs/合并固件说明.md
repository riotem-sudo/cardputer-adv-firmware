## 一、合成思路

两个固件本体的能力差距是"字符串级"的，没法直接把两个 4.9MB 的镜像拼起来用，所以做法是**源码级合并**：

| 来源 | 拿走什么 | 丢掉什么 |
|---|---|---|
| A：`Bruce-m5stack-cardputer-1.17-zh.bin`（sunshinexk 中文化，源码基线） | 全量中文界面、1.17 新特性（ProtoPirate 车钥匙、Chrysler/Ford/Kia/Mazda 协议、RTL 32-bit seed search 等 31 种 SubGHz 协议、EMV 新读写引擎） | 1.16.1 那套旧 EMV 品牌识别文案 |
| B：`Bruce1.16.1.bin`（JosephCGS ADV-CC1101-NRF24L01-IR） | Cardputer ADV 的 Cap-CC1101 引脚方案（CS=5 / GDO0=15 / POWER_EN=3 / SW0=13）、NRF24（CS=6 / IO0=4）、IR 发射引脚集合、EMV 读卡品牌识别思路 | 英文界面、旧版本功能集 |

编译用的是 A 的完整 PlatformIO 源码（仓库 `sunshinexk/Bruce-Cardputer-zh`，版本串 `1.17-zh`），不改中文语言包，只动硬件与 EMV 两块。

## 二、实际改了什么（源码级，两处）

### 1）ADV Cap-CC1101 成为默认引脚（开箱即用）

文件 `boards/m5stack-cardputer/interface.cpp`：

```cpp
#define CAP_CC1101_GDO0_PIN 15
...
#ifdef CAP_CC1101_SS_PIN       // ADV 板（m5stack-cardputer.ini 里已定义）
    CC1101_bus.cs  默认 = CAP_CC1101_SS_PIN   (5)
    CC1101_bus.io0 默认 = CAP_CC1101_GDO0_PIN (15)
#else                          // 老 Cardputer，保持原样
    cs=-1, io0=5
#endif
```

为什么必须改：原固件 `CC1101_bus.io0` 默认是 **5**，而 Cap-CC1101 上 **5 是 CS**、真正的中断脚 GDO0 是 **15**。不改的话 SubGHz 要么发不出、要么收不到（`rf_listen.cpp` 在 io0 上 `attachInterrupt`）。

Cap-CC1101 全套硬件宏（来自 `boards/m5stack-cardputer/m5stack-cardputer.ini`，编译时已生效）：

| 功能 | 引脚 |
|---|---|
| CC1101 CS | 5 |
| CC1101 GDO0 | 15 |
| CC1101 电源使能 POWER_EN | 3 |
| CC1101 波段开关 SW0 | 13 |
| CC1101 SCK / MISO / MOSI | 40 / 39 / 14 |
| NRF24 CS / IO0 | 6 / 4（与 NFC 的 SS 复用） |
| NFC(SPI) SS / IRQ | 6 / 4 |
| RGB LED | 21 |
| IR TX 默认 | 44（可选 3/4/5/6/13/15） |

`rf_utils.cpp` 里有联动逻辑：当 `CC1101_bus.cs == CAP_CC1101_SS_PIN` 时会自动拉高 POWER_EN、并按频段驱动 SW0 波段开关 —— 所以 SubGHz 用 433/315/868 都能直接切，不用手动接线。

引脚随时可改：`配置 → 设置设备引脚`。

### 2）EMV 补回"卡组织识别"兜底

1.17 的 EMV 引擎是重写过的（`emv_protocol.cpp` + `emv_reader.cpp`），品牌只靠卡片自己的 tag 0x50 Application Label 取，遇到不带 label 的卡就显示不出来。1.16.1 魔改版是靠 AID + PAN 前缀硬判 `VISA card detected` / `MasterCard`。

合并做法：在 `src/modules/rfid/emv_reader.cpp` 增加 `brandFromAid()`，按 AID 前缀映射卡组织，label 为空时回退到品牌名：

| AID 前缀 | 品牌 |
|---|---|
| A000000003 | VISA |
| A000000004 | MasterCard |
| A000000004 10 / 06 | Maestro |
| A000000025 | Amex |
| A000000065 | JCB |
| A000000333 | UnionPay |
| A000000152 / 65 | Discover |

同时完整保留 1.17 的 EMV 读写能力（读 PAN / 有效期 / 持卡人名，模拟与嗅探），并没有退回 1.16.1 的旧实现。

### 3）没合并的部分（说明清楚，别期待）

- **ADVLED**：1.16.1 里有这个字符串，但上游 1.16.1 源码里**不存在**这个模块，是 JosephCGS 私有改动、没开源。无法可靠复刻，直接跳过。
- **旧 EMV 的 PAN workaround 提示文案**（`PAN parsed with/without workaround`）：属于旧引擎的打补丁逻辑，新引擎不需要。

## 四、刷机

### 方式 A：esptool（推荐，命令行）

合并镜像刷 **0x0**：

```bash
esptool.py --chip esp32s3 -p COM5 -b 460800 \
  write_flash --flash_mode dio --flash_freq 80m --flash_size 8MB \
  0x0 "Bruce-CardputerADV-1.17-zh-CC1101-NRF24-IR_合并.bin"
```

或者用包里拆开的三个文件分别写（等价）：

```bash
esptool.py --chip esp32s3 -p COM5 -b 460800 \
  write_flash --flash_mode dio --flash_freq 80m --flash_size 8MB \
  0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware_app.bin
```

要点：
- 端口按你机器实际（你的 Cardputer ADV 常驻 **COM5**）。
- 只写 0x0 ~ 0x4C7BD0 范围，**spiffs（0x4F0000）不会被覆盖**，原来的录音/音频/设置文件都还在。
- 想彻底清干净加 `--erase-all`（会连 NVS 和 spiffs 一起清，配置回默认）。

### 方式 B：M5Launcher / SD 卡

把合并 bin 丢进 SD 卡根目录，M5Launcher 里选 OTA/自定义固件刷入即可（走 0x0 全量镜像，和上面等价）。

### 刷完自检

1. 开机进主菜单，界面应为中文。
2. `配置 → 设置设备引脚` 看 CC1101：CS=5、GDO0=15（若是 -1/5 说明刷错了包）。
3. 进 `SubGHz`，用遥控器测 433MHz 录制 —— 能收到波形说明 POWER_EN/SW0 都在工作。
4. `RFID → EMV` 贴一张银行卡，应显示品牌（VISA/MasterCard/银联…）。

## 六、RF 暴力破解增强（移植自 Flipper 的 Sub-GHz BruteForcer 4.0）

原来 `RF → Bruteforce` 只有 6 条协议，现在 8 条：

| 协议 | 位宽 | 时序（zero / one） | 说明 |
|---|---|---|---|
| Came 12bit | 12 | {-320,640} / {-640,320} | 原 |
| Nice 12bit | 12 | {-700,1400} / {-1400,700} | 原 |
| Ansonic 12bit | 12 | {-1111,555} / {-555,1111} | 原 |
| Holtek 12bit | 12 | {-870,430} / {-430,870} | 原 |
| Linear 10bit | 10 | {500,-1500} / {1500,-500} | 原 |
| Chamberlain 9bit | 9 | {-870,430} / {-430,870} | 原 |
| **Princeton 24bit（PT2262）** | 24 | {350,-1050} / {1050,-350} | 新增，TE=350µs，1:3 编码，stop=1TE + guard 30TE |
| **LinearDelta3 8bit** | 8 | {500,-1500} / {1500,-500} | 新增，Linear 家族 8bit |

数据来源：Princeton 采用 Flipper 官方编码器常量（`te_short=390/te_long=1170` 的 1:3 比例）+ SubBute 对 PT2262 芯片的实测 TE=350µs；不是凭记忆填的。

**新增 Bit 位宽选择**：菜单里多了 `Bits: N/24`，可选 4 ~ 协议满位。

原因：Princeton 全码是 2^24 = 16,777,216 条，每条至少 24bit × 3 段脉冲 ≈ 25ms，全扫要 4 天。实际用法是猜低位/已知前缀，按 12bit（4096 条，约 2 分钟）或 16bit 扫即可。Flipper 那个 FAP 的 `Bit: %d` 也是同一个思路。

进度显示改成十六进制（`1A3F/FFFFFF Princeton 24bit`），每 100 条刷新一次。

### UNILARM 25bit：独立菜单，分段定向发射

`RF → UNILARM拨码`（英文名 `UNILARM (DIP)`），不做 2^25 全码扫描，逻辑是：

- 帧 = `16bit 地址 + 9bit 指令` 拼成 25bit，MSB 先发；
- 脉形：bit0 = 高 150µs + 低 650µs，bit1 = 高 550µs + 低 250µs（TE≈209µs，社区实测值，非官方编码器常量）；
- 每帧后补 4ms 间隔；
- 地址空间 65536 切成 **16 段 × 4096**，菜单里选 `Address: 0-FFF / 1000-1FFF …`，一段跑完约 5 分钟（4 repeats），跑得完、可中断；
- 指令位可选 4 组：`Btn1 110000000`、`Btn2 001100000`（官方公开的两组）、`All0`、`All1`；
- 频率从固件频率表选（默认 433.92，330MHz 也支持）。

为什么不用 65536 分 8 段 → 用 4096 段：按 25bit × 每条约 20ms + 4 repeats 估算，4096 条 ≈ 5.5 分钟，正好一次刷机测试的耐心上限。

**注意**：这组脉形来自第三方实测文档，不是官方 `unilarm.c` 的编码器常量（那个文件抓取一直 404）。发出去能不能被门机接收，得你拿实机验证；如果无效，把 `ul_send_frame()` 里 150/650/550/250 四个数按你抓到的波形改一下再编即可。

## 九、已知限制

- CC1101 的 CS=5 / GDO0=15 是 Cap-CC1101 官方接线推断值；若你的板子是自己飞线的，用 `设置设备引脚` 改。
- IR 发射默认 44，若用 ADV 的 Cap-IR（3/4/5/6/13/15）在设置里切。
- 无 ADVLED 功能。
- 版本号保持 `1.17-zh`（这就是它的真实基线），没有伪造成别的版本。
